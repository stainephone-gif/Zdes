# Спайк недели 1: проверка распознавания

Цель — за 2–3 дня получить цифру, от которой зависит вся архитектура: **какой
процент реальных фотографий табличек приводит к верной персоне**.

Мы меряем не «качество OCR», а сквозной результат. Это принципиально: текст
с OCR пользователю никогда не показывается, он нужен только чтобы выбрать одну
запись из заранее проверенного списка гео-кандидатов. Плохо прочитанная
фамилия — не ошибка, если она всё равно указала на верного человека.

## Что делать

### 1. Собрать фотографии

60 снимков минимум, распределение по условиям — из `docs/03-test-plan.md` §1.1.
Обязательно включить блики, сумерки и съёмку под углом: именно там всё ломается.
Одну и ту же табличку полезно снять в разных условиях.

### 2. Заполнить ground truth

Скопируйте `ground_truth.example.csv` в `ground_truth.csv` и впишите реальные
данные: имя человека с таблички, годы, координаты, условия съёмки.
Строка с пустой фамилией — заведомо негодное фото, проверка корректной деградации.

### 3. Установить движки

Ставьте только те, что собираетесь сравнивать — недоступные пропускаются сами.

```bash
pip install pillow requests

# PaddleOCR, кириллическая модель PP-OCRv5 — локально, бесплатно
pip install paddlepaddle paddleocr

# Tesseract 5 — локально, бесплатно, есть Android-порт
apt install tesseract-ocr tesseract-ocr-rus && pip install pytesseract

# Claude — мультимодальная модель, сразу возвращает разбор таблички
pip install anthropic
export ANTHROPIC_API_KEY=...

# Yandex Vision OCR
export YC_IAM_TOKEN=... YC_FOLDER_ID=...

# Google Cloud Vision
export GCV_API_KEY=...
```

### 4. Запустить

```bash
python3 spike/ocr_bench/bench.py --photos ./photos --truth ./ground_truth.csv
```

Сравнить два движка на реальных данных:

```bash
python3 spike/ocr_bench/bench.py --photos ./photos --engines paddle,claude
```

Проверить, как деградирует качество при плохой геолокации (больше кандидатов
в радиусе — сложнее выбрать):

```bash
python3 spike/ocr_bench/bench.py --photos ./photos --candidates 30
```

## Как читать результат

| Метрика | Что означает | Порог |
|---|---|---|
| RSR | верная персона первая в списке | ≥ 80% |
| top-3 | верная персона попала в тройку | ≥ 92% |
| уверенно | показали бы карточку сразу, без экрана выбора | чем выше, тем лучше UX |
| **ложных** | **из показанных сразу — не тот человек** | **≤ 2%** |

«Ложных» важнее RSR. Честное «не смог прочитать» пользователь прощает,
уверенно показанного не того человека — нет.

## Решение по итогам

- Движок с лучшим RSR при «ложных» ≤ 2% и приемлемой ценой становится основным.
- Если разрыв между лучшим локальным (paddle/tesseract) и лучшим облачным
  меньше 10 п.п. — берём локальный: он бесплатный и не зависит от внешнего API.
- Второй по качеству остаётся как фолбэк для фото, где первый дал низкий скор.
- Результат записать в `docs/04-ADR-001-raspoznavanie.md` в раздел «Проверка».

## Отдельный вопрос: как быстро деградирует качество без геолокации

`--candidates` управляет тем, сколько табличек попало в радиус. Прогоните
6 / 30 / 100 и посмотрите, насколько падает RSR. Это показывает, сколько
точности даёт гео-фильтр — и что произойдёт, если пользователь запретит доступ
к местоположению. Модель этого эффекта без фотографий: `spike/name_match_sim.py`.
