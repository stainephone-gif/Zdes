# Сколько мемориальных табличек есть в OpenStreetMap

Первое, что надо выяснить перед выбором коридоров: где автозаполнение вообще
сработает. Коридор без данных в OSM собирается только в поле и при одном
редакторе не окупается.

Запрос выполняется на https://overpass-turbo.eu — вставить, нажать «Выполнить».

## Подсчёт по всему центру

```
[out:json][timeout:90];
(
  nwr["memorial"="plaque"](55.720,37.540,55.800,37.690);
  nwr["memorial:type"="plaque"](55.720,37.540,55.800,37.690);
  nwr["historic"="memorial"]["inscription"](55.720,37.540,55.800,37.690);
);
out count;
```

## Выгрузка с тегами — то, что пойдёт в импорт

```
[out:json][timeout:90];
(
  nwr["memorial"="plaque"](55.720,37.540,55.800,37.690);
  nwr["memorial:type"="plaque"](55.720,37.540,55.800,37.690);
  nwr["historic"="memorial"]["inscription"](55.720,37.540,55.800,37.690);
);
out center tags;
```

Полезные теги в ответе:

| Тег | Что даёт |
|---|---|
| `inscription` | текст надписи — сразу и в базу, и как эталон для проверки OCR |
| `subject:wikidata` | идентификатор персоны: отсюда тянутся годы, род занятий, связи |
| `name` | подпись объекта |
| `addr:street`, `addr:housenumber` | адрес дома |
| `start_date` | год установки |

## Подсчёт по коридорам

Заменить bbox на прямоугольник вокруг коридора и прогнать `out count;`
отдельно для каждого. Формат bbox: `(юг, запад, север, восток)`.

Ориентировочные рамки предложенных коридоров (уточнить по карте):

| Коридор | bbox |
|---|---|
| Пречистенка — Остоженка | `(55.735,37.585,55.750,37.605)` |
| Арбат — Поварская — Никитская | `(55.746,37.578,55.760,37.605)` |
| Чистые пруды — Мясницкая — Покровка | `(55.756,37.630,55.768,37.652)` |

## Как читать результат

- **Больше 60 записей в коридоре** — отлично, автозаполнение закрывает основную
  массу, полевой сбор только дополняет.
- **20–60** — рабочий вариант, часть придётся добавлять с телефона на месте.
- **Меньше 20** — коридор отпадает, берём следующий по списку.

Записать полученные числа сюда же и по ним зафиксировать выбор трёх коридоров
в `docs/06-content-plan.md` §2.

## Персоналии из Wikidata

По `subject:wikidata` из выгрузки — запрос на https://query.wikidata.org:

```sparql
SELECT ?person ?personLabel ?birth ?death ?occupationLabel ?article WHERE {
  VALUES ?person { wd:Q1234 wd:Q5678 }   # идентификаторы из тега subject:wikidata
  OPTIONAL { ?person wdt:P569 ?birth. }
  OPTIONAL { ?person wdt:P570 ?death. }
  OPTIONAL { ?person wdt:P106 ?occupation. }
  OPTIONAL {
    ?article schema:about ?person;
             schema:isPartOf <https://ru.wikipedia.org/>.
  }
  SERVICE wikibase:label { bd:serviceParam wikibase:language "ru". }
}
```

Отсюда берутся годы жизни, род занятий и ссылка на статью — то есть три из
шести полей карточки заполняются без участия редактора.

## Постройки: что эти люди создали в городе

Для архитекторов, инженеров и скульпторов произведение — это не ссылка,
а объект в городе с координатами. Проверяем, сколько таких объектов есть
в Wikidata по нашим персонам.

```sparql
SELECT ?person ?personLabel ?work ?workLabel ?role ?coord ?built ?typeLabel WHERE {
  VALUES ?person { wd:Q1234 wd:Q5678 }   # идентификаторы из subject:wikidata

  {  ?work wdt:P84  ?person. BIND("architect" AS ?role) }   # архитектор здания
  UNION
  {  ?work wdt:P631 ?person. BIND("engineer"  AS ?role) }   # инженер-конструктор
  UNION
  {  ?work wdt:P170 ?person. BIND("sculptor"  AS ?role) }   # автор памятника

  ?work wdt:P625 ?coord.                 # без координат постройка нам не нужна
  OPTIONAL { ?work wdt:P571 ?built. }
  OPTIONAL { ?work wdt:P31 ?type. }
  SERVICE wikibase:label { bd:serviceParam wikibase:language "ru". }
}
```

Что смотреть в результате:

- **Сколько персон из наших коридоров получили хотя бы одну постройку.** Если
  меньше четверти — блок «Что он построил» переносится в P2, он не окупит
  разработку.
- **Сколько построек попадает в пешую доступность** (до 2 км от таблички).
  Это и есть ценность функции: постройка за сорок километров — это ссылка,
  постройка за четыреста метров — это повод пройтись.

## Автор дома, на котором висит табличка

Здания в OSM часто несут тег `wikidata`. Через него у дома находится
архитектор, и это даёт связь для **любой** таблички, даже если у самой
персоны нет ни одного произведения.

```
[out:json][timeout:90];
way["building"]["wikidata"](55.720,37.540,55.800,37.690);
out center tags;
```

Дальше по полученным идентификаторам — свойство P84 в Wikidata. Посчитать,
у какой доли зданий в коридорах есть такой тег: это верхняя граница
автоматического заполнения связи «кто построил этот дом».
